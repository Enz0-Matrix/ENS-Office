## П1. Функции, без которых Р7 не заменить

**Форматы файлов**
- Открытие `.xls`, `.ods`, `.csv` (сейчас только сообщение «это не книга Excel», `desktop.ts:172–195`). CSV — минимум: импорт с выбором кодировки (UTF-8/1251) и разделителя, сохранение листа в CSV.
- Сохранение в `.ods` (для госзаказчиков, у которых ODF обязателен).

**Данные**
- Сводные таблицы (создание, обновление, сохранение в xlsx) — нет ни в движке, ни в интерфейсе.
- «Форматировать как таблицу» (Ctrl+T), структурированные ссылки в интерфейсе, строка итогов (зависит от 0.1).
- Удалить дубликаты; Текст по столбцам; Консолидация; Подбор параметра; Прогрессия (окно заполнения).
- Срезы и спарклайны (хотя бы показ и сохранение без потерь).

**Формулы и проверка**
- Зависимые ячейки (есть только «Влияющие ячейки»), «Вычислить формулу» по шагам, проверка ошибок (зелёный уголок), окно контрольного значения.
- Режим вычислений «Вручную» и итеративные вычисления (циклические ссылки с итерациями, как в Excel).

**Оформление и правка**
- Формат по образцу (кисть); стили ячеек (галерея «Стили ячеек»).
- Разделение окна (Вид → Разделить).
- Проверка орфографии без интернета (общая задача с ENS-Text, словари).
- Работа с группой листов (правка сразу на нескольких выделенных листах).

**Хвосты из бэклога**
- П. 19 ◐: rich text — показ оформления в самом поле ввода, сохранение при копировании и вставке.
- П. 7 ⏸: насыщенность палитры заливки (отложено).
- «Следующее»: пересчёт ссылок при частичном удалении правила условного форматирования с формулой; печать — `Print_Titles` как в Excel и разбивка широких таблиц по столбцам.
- Совместное редактирование (у Р7 есть; у нас вне плана — решить, нужно ли для «полной замены»).

## П2. Расхождения с Excel: формулы

В движке 497 функций (`generate_language/src/languages.json`). Отсутствуют или не считаются:

| Функция | Состояние | Важность |
|---|---|---|
| `AGGREGATE` (АГРЕГАТ) | нет | высокая: часто в отчётах с фильтрами |
| `FORECAST.ETS`, `.CONFINT`, `.SEASONALITY`, `.STAT` | `#N/IMPL!` (`functions/statistical/forecast.rs`) | средняя |
| `GETPIVOTDATA` | нет (нет сводных) | вместе со сводными |
| `GROUPBY`, `PIVOTBY`, `IMAGE` | нет | низкая, новые функции Excel 365 |
| `WEBSERVICE`, `FILTERXML`, `STOCKHISTORY`, `TRANSLATE`, `DETECTLANGUAGE` | нет | низкая (сеть) |
| `BAHTTEXT`, `PHONETIC`, `JIS`, `DBCS`, `EUROCONVERT`, `CUBE*`, `CALL`, `SQL.REQUEST` | нет | очень низкая |

Поведение:
- Неявное пересечение не реализовано в части функций: при передаче массива/диапазона туда, где Excel берёт одну ячейку, получаем `#N/IMPL!` (`functions/text/common.rs`, `statistical/count_and_average.rs`, `logical/and_or_xor_not.rs`, `statistical/rank_eq_avg.rs`). [код]
- Нужна сверка с эталоном Excel на наборе из «Сверки ТС»: `SUBTOTAL(9/109)` при автофильтре (последняя строка как «строка итогов»), `IF` без «иначе» в текстовом формате, `XLOOKUP` по целым столбцам (скорость). [док]
- Известное: 4 теста функций Бесселя на аргументах 10¹⁰–10¹² падают в Windows-сборке GNU (погрешность libm). [док]

## П2. Расхождения с Excel: числовые форматы

| Что | Как у нас | Как в Excel | Где |
|---|---|---|---|
| Заполнитель `*x` (например, бухгалтерский `_-* # ##0 ₽_-`) | один пробел вместо заполнения ширины ячейки: знак валюты не прижимается к краю | символ повторяется до ширины ячейки | `base/src/formatter/format.rs` (`TextToken::Spacer`), отрисовка в `grid.ts` |
| Локаль в коде `[$-419]`, `[$€-fr-FR]` | локаль игнорируется (символ валюты берётся) | меняет названия месяцев и дней | `formatter/lexer.rs:356–376` |
| Системные форматы `[$-F800]` (длинная дата), `[$-F400]` (время) | разбираются как обычная локаль, без подстановки системного формата | длинная дата / время по системе | `formatter/lexer.rs` |
| `[DBNum1..3]` (числа иероглифами/прописью) | не поддерживается | поддерживается | — |
| Формат `_x` (отступ на ширину символа) | один пробел | отступ на ширину символа `x` | `format.rs` (`Ghost`) |

Проверить тестами и сравнить с Excel (могут совпадать, но не видел тестов): `[h]:mm` для отрицательных значений, округление дробей `# ?/?` у границ, `General` для очень малых и больших чисел (экспонента), `@` с числом.

## П3. Качество и проверки

- **У ENS-Table нет тестов интерфейса**: в `app/table/package.json` нет `npm test`, в `ci.yml` проверки Playwright идут только для ENS-Text. Нужен набор Playwright (Chromium 128) хотя бы для: ввода, формул, копирования, сохранения xlsx.
- Нет корпуса реальных xlsx для круга «открыть → сохранить → открыть»: в `app/text/tests/fixtures` только docx. Нужны файлы Excel и Р7 (с таблицами, сводными, условным форматированием, макросами, датами 1904).
- Нет автоматической сверки формул с Excel: нужен набор xlsx с кэшем значений, сохранённым именно в Excel, и тест «пересчитать и сравнить» (в IronCalc механизм `Comparison` уже есть).
- `app/table/CLAUDE.md`: раздел «Рабочий список» пока заглушка — после согласования этого списка перенести в него ссылку сюда.
- Сообщения об ошибках xlsx в движке на английском и со ссылкой на `support@ironcalc.com` (`xlsx/src/error.rs`) — проверить, не видит ли их пользователь.
