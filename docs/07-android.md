# ENS-Table под Android — проба и оценка (29.10.2026)

Это не план выпуска, а честная оценка: что даёт Tauri 2 «бесплатно», что
придётся переделать и сколько это займёт. Настольные сборки, движок и формат
файлов не меняются.

## 1. Что проверено

| Проверка | Итог |
|---|---|
| Оболочка `app/table/src-tauri` компилируется под `aarch64-linux-android` (`cargo check`, без NDK) | да, без правок кода |
| `lib.rs` уже размечен для мобильных (`#[cfg_attr(mobile, tauri::mobile_entry_point)]`, `crate-type = staticlib, cdylib, rlib`) | да |
| Плагины `dialog` и `clipboard-manager` есть под Android | да (но диалог отдаёт `content://`, см. §3.1) |
| Полная сборка apk | собирается в CI (задание «Сборка Android (проба)», кнопка Run workflow): отладочный apk arm64, архив артефакта ≈ 42 МБ (отладочная сборка без сжатия Rust; выпускная будет заметно меньше). Сборка ≈ 7 мин |
| Интерфейс в Chromium с эмуляцией телефона (Playwright, Pixel 7, 412×839) | касание выбирает ячейку; двойное касание открывает редактор, ввод «123» + Enter записан; протяжка пальцем диапазон **не** выделяет; 59 из 61 видимой кнопки меньше 44 px; лента занимает ~40 % высоты экрана; горизонтальной прокрутки страницы нет; ошибок JS нет |

**Почему не здесь.** Для сборки нужны Android SDK (platform 34+, build-tools),
NDK (r26+), Java 17+, цели Rust `aarch64-linux-android` (телефоны),
`armv7-linux-androideabi` (старые дешёвые), `x86_64-linux-android` /
`i686-linux-android` (эмуляторы). В облачной среде есть Java 21 и Rust с целью
aarch64, но SDK и NDK качаются с dl.google.com — прокси его не пускает.
На сервере GitHub (`ubuntu-latest`) SDK и NDK уже стоят, поэтому проба — в CI.

**На своей машине:** Android Studio (ставит SDK, NDK, эмулятор), затем
```
rustup target add aarch64-linux-android x86_64-linux-android
export NDK_HOME=$ANDROID_HOME/ndk/<версия>
cd app/table && npm ci && npm run engine
npx tauri android init      # создаёт src-tauri/gen/android (в git не кладём)
npx tauri android dev       # телефон по USB или эмулятор
```

Для Android задан отдельный идентификатор `ru.ensoffice.table`
(`src-tauri/tauri.android.conf.json`): дефис из `ru.ens-office.table` нельзя
в имени пакета Java/Kotlin. Этот файл читается только при сборке под Android.

## 2. Что работает в мобильном WebView как есть

Android System WebView — это Chromium, поэтому:
- движок IronCalc в WebAssembly, формулы, чтение и запись xlsx — всё внутри
  страницы, без системных вызовов;
- сетка на Canvas (с учётом `devicePixelRatio`), прокрутка пальцем — у сетки
  обычная прокручиваемая область;
- одиночное касание = щелчок (WebView сам шлёт `mousedown/mouseup/click`):
  выбрать ячейку, нажать кнопку ленты, открыть вкладку;
- двойное касание → редактор ячейки, появляется экранная клавиатура, ввод
  идёт в обычное поле;
- шрифты (Carlito и др.) лежат в приложении — сеть не нужна;
- буфер обмена — плагином Tauri;
- папка восстановления `app_local_data_dir()/recovery` — внутренняя память
  приложения; `recovery.rs` пишет туда обычными файлами, это на Android работает.

## 3. Что придётся переделать

### 3.1. Файлы: системный диалог вместо путей (главное)
На Android нет «путей к файлам» у пользователя. Системный диалог (Storage
Access Framework) отдаёт адрес `content://…`, а `files.rs` работает через
`std::fs` с путём — открыть и сохранить так нельзя.
- Чтение: `ContentResolver.openInputStream(uri)` — маленький плагин на Kotlin
  (или `tauri-plugin-fs`, если его поддержка `content://` окажется достаточной —
  проверить на телефоне).
- Сохранение: атомарной замены через SAF **нет** (запись идёт «поверх»,
  режим `"wt"`). Замена ADR-005 для Android: сначала копия во внутреннюю
  память → запись в `content://` → перечитать и сверить → при ошибке копия
  остаётся, сообщение и «Сохранить как…».
- «Файл изменили снаружи»: `DocumentsContract.COLUMN_LAST_MODIFIED` — у части
  хранилищ (облака, мессенджеры) его нет, проверка будет не везде.
- Права: `takePersistableUriPermission`, иначе после перезапуска файл из
  «Недавних» не откроется.
- Имя и тип файла — `OpenableColumns.DISPLAY_NAME`, тип по-прежнему по
  содержимому (`detect_kind` переиспользуется как есть).
- «Открыть с помощью» (из Загрузок, почты, мессенджера) — фильтр Intent
  `ACTION_VIEW` для xlsx в манифесте и передача URI в интерфейс вместо
  `startup_file`.

### 3.2. Окна
Мобильный Tauri — одно окно. `openWindow` (вторая книга, исходник рядом с
восстановленной) на Android не работает: в `openPath` — спросить «Сохранить?»
и заменить книгу (позже — список открытых книг). Свой заголовок окна с
кнопками (`decorations: false`) на телефоне скрыть.

### 3.3. Жесты и крупные элементы интерфейса
Сетка слушает только `mousedown/mousemove/mouseup`. Касание превращается в
щелчок, но **протяжка пальцем — это прокрутка**, `mousemove` не приходит. Не
работают: выделение диапазона, маркер заполнения, ширина столбцов, перенос
рисунков, подменю по наведению (`mouseenter`). Нужно:
- перевести сетку на Pointer Events; ручки выделения как в мобильном Excel;
- долгое нажатие = контекстное меню; щипок = масштаб (сейчас Ctrl+колесо);
- «режим касания»: кнопки ленты и пункты меню не меньше 44–48 px, упрощённая
  лента (Главная и пара вкладок), видимые «Отменить/Вернуть» вместо Ctrl+Z;
- экранная клавиатура закрывает пол-экрана: прокручивать к редактируемой
  ячейке, строка формул над клавиатурой;
- ввод «с листа» (начать печатать по выделенной ячейке) ловится через
  `keydown` по документу — на телефоне клавиатуры нет, пока нет фокуса в поле;
  нужен постоянный скрытый `input` или кнопка «Ввод». Клавиатуры Android
  (Gboard и др.) шлют `keyCode 229` и события composition — проверять на
  реальном устройстве.
- печать (`window.print`) в WebView Android не работает — убрать или «Поделиться PDF» позже.

### 3.4. Восстановление после сбоя и журнал без папок на диске
- Папку выбрать нельзя: `recovery.root/setRoot`, `pickFolder` — скрыть.
- **Android сам убивает приложение в фоне** — это не сбой. Снимок делать при
  `visibilitychange → hidden` (= onPause), а при следующем запуске молча
  поднимать книгу, а не пугать «программа завершилась аварийно».
- Признак «живого» сеанса (`alive.lock` + пульс) работает, но смысл другой:
  сеанс почти всегда «упал». Нужен флаг «уходили в фон штатно».
- Журнал изменений (кто правил) — имя пользователя ОС недоступно
  (`user_name` вернёт пусто): спросить имя в настройках.
- `history.rs` (копии ENS-Text) не трогаем.

### 3.5. Память и большие книги
- Процесс WebView на телефоне с 3–4 ГБ ОЗУ система убивает раньше, чем
  на ПК; приложение получит «белый экран» (render process gone).
- Сейчас при сохранении и снимке книга живёт в памяти несколько раз: модель
  → `toBytes`/`toXlsx` → `Uint8Array` → передача в Rust. На ПК это незаметно,
  на телефоне книга 50 МБ xlsx может не открыться.
- Нужно: замер на реальных файлах (`tests/corpus/public`) на дешёвом
  телефоне; предупреждение «книга большая, открыть только для просмотра»;
  реже снимки, без двойных копий; восстановление после «белого экрана»
  (Tauri умеет перезагрузить страницу — книга поднимется из снимка).

### 3.6. Мелочи
- `open_target` (ссылки) → Intent / `tauri-plugin-opener`.
- Подпись и распространение: свой ключ (хранить вне репозитория), RuStore
  или прямой apk; `minSdk 24` (Android 7); ABI arm64-v8a, при необходимости
  armeabi-v7a. Размер apk — оценить по первой сборке CI.

## 4. Оценка срока

Оценка в рабочих неделях одного разработчика с ассистентом; погрешность большая,
пока apk не запущен на 2–3 реальных телефонах.

| Этап | Срок |
|---|---|
| 0. CI собирает apk, запуск на телефоне, замеры памяти | 2–4 дня |
| 1. Открыть .xlsx → посмотреть → поправить ячейку → сохранить (§5) | 2–3 недели |
| 2. Восстановление при уходе в фон, «Открыть с помощью», недавние файлы | 1–2 недели |
| 3. Сенсорный режим: выделение, ручки, контекстное меню, щипок, крупная лента | 4–6 недель |
| 4. Большие книги, дешёвые телефоны, подпись, RuStore | 2–3 недели |
| **До пригодной мобильной версии** | **≈ 2,5–3,5 месяца** |

Полное совпадение с настольной версией (все диалоги, диаграммы, печать) не
планируется: мобильный Excel тоже урезан.

## 5. Риски
1. **SAF и сохранение** — нет атомарной замены; поведение облачных
   провайдеров (Яндекс Диск, мессенджеры) разное. Это прямо задевает
   приоритет №1 (не терять данные).
2. **WebView на телефонах без Google Play** (Huawei, часть «китайцев»,
   защищённые сборки): старый WebView может не потянуть нужные возможности.
   Проверять минимальную версию Chromium при запуске.
3. **Клавиатуры Android и IME** — ввод в ячейку, автозамена, Enter.
4. **Память** — см. §3.5.
5. **Tauri mobile моложе настольного**: часть плагинов на Android урезана,
   придётся писать свой Kotlin-код.
6. **Нет телефонов для проверки в CI** — эмулятор в CI возможен
   (KVM на `ubuntu-latest`), но реальные жесты и клавиатуры — только руками.

## 6. Порядок шагов
1. Запустить в Actions «Сборка Android (проба)», поставить apk на телефон,
   записать, что видно и что падает.
2. Этап 1 (§7) за флагом `isMobile`, не меняя поведение на ПК.
3. Замер памяти на корпусе файлов → решение о пределе размера.
4. Восстановление при уходе в фон.
5. Сенсорный режим.
6. Подпись, RuStore.

## 7. Минимальный первый этап: открыть → посмотреть → поправить → сохранить

**Пользователь:** «Открыть» → системный выбор файла → книга на экране →
двойное касание ячейки → ввод → «Сохранить» (в тот же файл) или «Сохранить
как» (системный диалог создания файла).

### Что поменять в `platform.ts`
Принцип: «путь» становится непрозрачной строкой — на ПК это путь, на Android
адрес `content://`. `desktop.ts` и `Doc.path` менять почти не придётся.

- `isMobile` — признак Tauri на Android (`@tauri-apps/plugin-os` или
  `navigator.userAgent` + `isTauri`). `isDesktop` остаётся `true` (файлы и
  восстановление есть), окна и папки отключаются по `isMobile`.
- `pickOpen()` — диалог уже вернёт `content://…`; убрать `defaultPath`,
  фильтр — по MIME (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`),
  расширения Android не понимает.
- `pickSave()` — `ACTION_CREATE_DOCUMENT` (плагин dialog `save` на Android
  делает именно это; проверить, что возвращает URI).
- `inspectFile/readFile/saveFile` — те же имена команд; в Rust ветка
  `#[cfg(target_os = "android")]`: если строка начинается с `content://`,
  идти через плагин Kotlin (ContentResolver), иначе — как сейчас. Ответ
  `FileInfo.name` — из `DISPLAY_NAME`, а не из конца пути (`baseName` в
  `desktop.ts` для `content://` даёт мусор — брать `info.name`).
- `saveFile` на Android — копия во внутреннюю память → запись → сверка; ошибка
  `CHANGED_ON_DISK` — только если хранилище отдаёт дату изменения.
- `openWindow` — на Android не вызывать: в `openPath` заменять текущую книгу
  после вопроса «Сохранить?».
- `pickFolder`, `recovery.setRoot`, `openTarget` — скрыть или заглушки.
- `osUserName` — пусто (уже есть запасной вариант).
- `recovery.*`, буфер обмена, `ask` — без изменений.

### Вне `platform.ts`, но нужно для этапа 1
- Kotlin-плагин (~150–250 строк): чтение, запись, имя, дата по URI,
  постоянные права.
- Скрыть свой заголовок окна, печать и пункты про окна/папки на телефоне.
- Кнопки «Открыть / Сохранить / Отменить» крупно в верхней панели
  (без ленты, если она не помещается).
- Проверка Playwright с эмуляцией телефона: касание ячейки, двойное
  касание → ввод → Enter.

## 8. Первая проба на телефоне (30.10.2026)
apk из CI установился и запустился; таблица, лента, меню «Файл» работают,
снимки восстановления пишутся в `/data/user/0/ru.ensoffice.table/…`.
Найдено и исправлено:
- **«ожидались байты»** при снимке и сохранении: на Android Tauri шлёт
  команды через `postMessage`, и `Uint8Array` приходит в Rust JSON-массивом
  чисел, а не «сырыми» байтами. `files.rs::bytes_of` принимает оба вида.
  Медленнее на больших книгах — учесть в §3.5.
- **Шапка под вырезом камеры** и строка состояния под полосой жестов:
  `viewport-fit=cover` + отступы `env(safe-area-inset-*)` (на ПК они 0).
  Проверить на телефоне: старые WebView могут отдавать 0 — тогда отступы
  придётся передавать из Kotlin.
- **Меню «Файл» слишком широкое**, параметры обрезаны справа: на узком
  экране меню 132 px, строки параметров переносятся.
- **У. Болт «убегал» от каждого касания**: дрожь пальца считалась
  перетаскиванием. Теперь перетаскивание — от 10 px, двойное касание работает.

Вторая проба: отступ под камеру работает, меню «Файл» узкое. Доделано:
- вкладки ленты листаются вбок (раньше «Вид» и часть других были недоступны),
  кнопок окна на телефоне нет, поиск ужимается;
- группы ленты не сжимаются в столбик: «Главная» по высоте 114 px вместо 240,
  лента листается вбок;
- Болт всё же «убегал»: облачко с фразой стояло над ним в одном блоке, и после
  перетаскивания (блок привязан к верху) каждое касание сдвигало Болта на высоту
  облачка. Облачко теперь поверх, у края экрана — снизу или сбоку.

Не сделано: лента под телефон по-настоящему (крупные кнопки, упрощённые вкладки) — этап 3.
