# Журнал решений (ADR)

## ADR-001. Стек (принято 17.10.2026)
Tauri 2 (Rust) + веб-интерфейс на TypeScript. Таблицы — IronCalc (MIT/Apache-2.0).
Документы — модель + своя постраничная вёрстка; docx через docx-rs (MIT).
Отклонены: ONLYOFFICE (AGPL, основа Р7), HyperFormula (GPL), WPS (проприетарный).

## ADR-002. Интерфейс: узнаваемость Office (принято)
Раскладка лент, вкладок, горячих клавиш как в Office 2021–2024. Иконки — Fluent UI
System Icons (MIT). Шрифты — Carlito, Caladea, Liberation. Названия: Ens-Office,
ENS-Tekst, ENS-Table.

## ADR-003. Команды отдельно от ленты (принято)
Каждое действие = `command_id` в реестре команд. Лента, меню, горячие клавиши,
контекстное меню — только ссылки на команды. Лента описывается декларативно
(YAML/JSON) с полем `feature_module` → основа модульной установки.

## ADR-004. Univer или своя сетка — ОТКРЫТО
Нужен прототип (1–2 недели): открыть лист «ВСЕ Филиалы» (50 тыс. ячеек, 15 тыс.
формул) в (а) Univer, (б) своей Canvas-сетке + IronCalc. Сравнить время открытия,
прокрутку, пересчёт, память. Решение — по цифрам.

## ADR-005. Надёжность сохранения (принято, приоритет №1)
- Исходный файл меняется только по «Сохранить».
- Сохранение: временный файл рядом → проверка (перечитать) → атомарная замена;
  на SMB/WebDAV — отдельная стратегия с резервной копией.
- Журнал восстановления — отдельно, в профиле пользователя.
- Любая ошибка сохранения → понятное сообщение + «Сохранить как…».
- Тип файла — по содержимому (ZIP + `[Content_Types].xml`), не по расширению.
