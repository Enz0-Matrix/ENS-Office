# Прототип №1: Univer или своя сетка + IronCalc (17.10.2026)

Код: [prototypes/grid-bench](../../prototypes/grid-bench/). Запуск — в README там же.

## Методика
- Синтетический обезличенный лист по образцу «ВСЕ Филиалы»: N строк × 10 столбцов,
  справочник 2000 строк. На строку 4 формулы: ВПР в справочник, произведение, ЕСЛИ,
  ОКРУГЛ; плюс итоговая СУММ по всем строкам.
- Вариант «без ВПР»: вместо ВПР — прямая ссылка `=Lookup!B123` (чтобы отделить
  стоимость поиска от стоимости объёма).
- Правильный итог считается независимо, по правилам Excel (ОКРУГЛ — половина от нуля,
  с поправкой на 15 значащих цифр).
- Правка: меняем одну ставку в справочнике → должны пересчитаться ~N/2000 строк и итог.
- Запуск в headless Chrome (без фонового троттлинга вкладок).
- Версии: IronCalc 0.8.4 (WebAssembly), Univer 1.0.4 (open-source preset sheets-core).

## Найденные проблемы

**IronCalc 0.8.4**
1. ❗ **ОКРУГЛ не совпадает с Excel**: ОКРУГЛ(1,005;2)=1 (Excel: 1,01),
   ОКРУГЛ(0,285;2)=0,28 (0,29), ОКРУГЛ(5,015;2)=5,01 (5,02). Отсюда неверный итог.
2. ВПР медленный: ~2 мс на один поиск по 2000 строк (линейный перебор без кэша).
3. Нет инкрементального пересчёта: правка одной ячейки пересчитывает всю книгу.
4. Загрузка через `setUserInput` растёт квадратично (50k строк — 192 с).
   Это путь «по одной ячейке»; нативная загрузка xlsx в Rust его обходит.
5. Отображение в формате «Общий» не обрезает до 15 значащих цифр (`6366933.449999999`).
6. В npm-пакете 0.8.3 отсутствует файл `snippets/…/inline0.js` — пакет не работает (в 0.8.4 исправлено).

**Univer 1.0.4**
1. ❗ Движок формул очень медленный и прожорливый: 50k строк — 67 с расчёта, 24 с на
   правку, 728 МБ памяти. Это ровно жалоба пользователей на Р7 («виснет»).
2. Сборка только модуля таблиц — 13 МБ JS.
3. Импорт/экспорт xlsx, совместная работа, сводные, диаграммы — в платной Pro-версии.
4. Плюсы: готовый интерфейс, плавная прокрутка (60 кадров/с), ОКРУГЛ верный.

## Вывод (→ ADR-004)
Ни одна основа «из коробки» не быстрее Excel. Но у IronCalc все проблемы — в ядре на Rust
с лицензией MIT/Apache, их можно исправить (и отдать исправления авторам). У Univer
главная проблема — архитектура движка формул на JavaScript; исправлять её — значит
переписывать ядро чужого проекта, а нужные нам функции (xlsx) ещё и платные.

**Решение: своя сетка + форк IronCalc, запускаемый нативно (Rust в Tauri, не wasm),
расчёт — в фоновом потоке.** Интерфейсные приёмы (отрисовка, прокрутка) изучаем у Univer.

## Первые задачи для движка ENS-Table (по приоритету)
1. ОКРУГЛ и родственные функции — точно как Excel + тесты на «половинки».
2. Формат «Общий»: 15 значащих цифр.
3. Индекс/кэш для ВПР, ГПР, ПОИСКПОЗ, ПРОСМОТРX (цель: 16 тыс. ВПР < 0,5 с).
4. Инкрементальный пересчёт по графу зависимостей.
5. Пакетная загрузка (xlsx → модель) без квадратичной сложности.
6. Отрисовка своей сетки: кэш видимых строк, цель — стабильные 60 кадров/с.
