# Движок ENS-Table, шаг 2: инкрементальный пересчёт (17.10.2026)

Было: любая правка пересчитывала всю книгу. Стало: пересчитываются только формулы,
которые (прямо или через цепочку) зависят от изменённых ячеек.

Код: `core/ironcalc/base/src/incremental.rs` + точечные врезки (помечены «ENS-Office»)
в `evaluation.rs`, `model.rs`, `functions/*`, `user_model/common.rs`.

## Как это работает
1. **Полный расчёт записывает зависимости.** Каждое чтение ячейки формулой
   (все чтения проходят через `evaluate_cell`) — одна запись в плоский список.
   Диапазоны, которые движок читает «напрямую» (константы, хвост целого столбца,
   индекс ВПР, ПРОМЕЖУТОЧНЫЕ.ИТОГИ) записываются прямоугольниками.
2. **Отпечатки ячеек.** После расчёта у каждой ячейки запоминается отпечаток:
   значение константы или текст формулы.
3. **Правка.** Перед пересчётом отпечатки сравниваются с текущими ячейками (слиянием,
   без хеш-таблицы). Так находятся *все* изменения, каким бы путём они ни пришли
   (ввод, вставка, отмена, автозаполнение, совместная работа).
4. **Грязные формулы** = изменённые ячейки + все, кто их читает, транзитивно
   (обратный индекс строится лениво, при первой правке).
5. **Частичный проход:** запускаются только грязные формулы; остальные отдают
   сохранённое значение.

## Когда выполняется полный пересчёт (ради точности)
- после загрузки (графа ещё нет);
- изменилась структура: листы, имена, таблицы, локаль, скрытые строки/столбцы;
- в книге есть массивы, которые «разливаются», CSE-массивы или `#ПЕРЕНОС!`
  (формула вроде ИНДЕКС/ПРОСМОТРX с одним значением — обычная формула);
- затронута больше чем половина формул;
- среди пересчитанных формул обнаружился цикл (у IronCalc результат циклов
  зависит от порядка обхода — полный пересчёт даёт тот же результат, что всегда).

Волатильные функции (ТДАТА, СЕГОДНЯ, СЛЧИС, СЛУЧМЕЖДУ, СЛУЧМАССИВ, ЯЧЕЙКА, ИНФОРМ)
пересчитываются при каждой правке, как в Excel.

Попутно: скрытие/показ строк теперь сразу пересчитывает ПРОМЕЖУТОЧНЫЕ.ИТОГИ(1xx),
как в Excel (в исходном IronCalc пересчёта не было вовсе).

## Проверка корректности
- 9 тестов `test_ens_incremental.rs`: зависимые формулы, пустые ячейки в диапазонах,
  целые столбцы, удаление, ВПР, новые/изменённые формулы, циклы, отмена/повтор,
  волатильные функции, откат на полный, скрытые строки.
- **Случайные тесты:** 400 случайных правок на листе (числа, текст, СУММ, ВПР, ЕСЛИ,
  СЧЁТЕСЛИ, ИНДЕКС/ПОИСКПОЗ, ПРОМЕЖУТОЧНЫЕ.ИТОГИ, очистка) — после *каждой* правки
  результат сравнивается с полным пересчётом. Два варианта: без циклов
  (>350 правок идут частичным путём) и с циклами. Прогнано на 40 разных
  случайных последовательностях — 0 расхождений.
- **Режим сверки** `ENS_VERIFY_INCREMENTAL=1`: весь набор IronCalc (~2780 тестов),
  после каждого частичного пересчёта — полный и сравнение *всех* ячеек. Чисто,
  в том числе в стресс-режиме `IRONCALC_MAX_DEPTH=1`. Проверено, что сверка ловит
  настоящие ошибки (найдено и исправлено 3: «пустая ячейка со стилем», формулы
  на цикле при раскрутке стека, `#ПЕРЕНОС!` при отмене).

## Замер (50 000 строк, ~200 тыс. формул, нативно)
| | Полный пересчёт | Частичный |
|---|---|---|
| Правка цены в одной строке (строка + итог) | ~1,2 с | **~70–90 мс** |
| Правка ставки в справочнике (63 строки + итог), первая правка после загрузки | ~1,2 с | ~330 мс (из них ~250 мс — построение обратного индекса, один раз) |
| Первый расчёт после загрузки | +13% к прежнему (запись зависимостей) | — |

Из ~75 мс правки: ~37 мс — сравнение отпечатков 450 тыс. ячеек, ~25 мс — сам
пересчёт (итоговая СУММ по 50 тыс. строк), ~10 мс — обновление индекса.

## Что можно ускорить дальше
- Журнал изменений вместо сравнения отпечатков (−35 мс на правку), с отпечатками
  как страховкой раз в N правок.
- Строить обратный индекс в фоновом потоке сразу после загрузки.
- Инкрементальная СУММ по большим диапазонам (пересчитывать разницу, а не всё).
- Частичный пересчёт и для «разливающихся» массивов.
