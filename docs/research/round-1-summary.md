## Задание 2 (GPT) — структура ленты
⚠ Сами YAML-файлы в ответ не попали (пришёл только комментарий). Нужно запросить ещё раз:
«Пришли полный текст word-ribbon-ru.yaml и excel-ribbon-ru.yaml в виде блоков кода».

Ценная идея, принята: **лента отделена от команд.** Кнопка, горячая клавиша и пункт
меню вызывают один `command_id`. Схема элемента ленты: `label, type, key, access_key,
icon, command_id, visibility, enabled_when, overflow_priority, feature_module`.
Поле `feature_module` связывает ленту с модульной установкой.

Рекомендация GPT снять скриншоты каждой вкладки реального Office — принята:
это самый точный эталон. (Задача для пользователя: если есть доступ к Office 2021/2024.)

## Задание 3 (Qwen) — функции Excel
Получено ~70 самых частых функций (полного списка нет). Полный список возьмём
из IronCalc / документации Microsoft отдельно.

⚠ Ошибки в ответе:
- UPPER = **ПРОПИСН**, а не ПРОПНАЧ (ПРОПНАЧ = PROPER).
- MROUND (ОКРУГЛТ) **не** банковское округление — тоже «от нуля».
- «SUM("5";5)=10» верно только для аргументов, введённых прямо в формулу;
  текст «5» **в ячейке диапазона** СУММ игнорирует. Это тонкое, но важное правило.
- Совет «взять WPS API / Apache POI / ONLYOFFICE» — отклонён (лицензии, Java, те же проблемы Р7).

Верные и важные «ловушки» (в тесты движка):
- Ошибка високосного 1900 года (29.02.1900 = число 60).
- Системы дат 1900/1904 (флаг `date1904`).
- ОКРУГЛ — от нуля (2,5→3), а не банковское.
- Пустая ячейка в арифметике = 0, но `0+""` = #ЗНАЧ!.
- Неявное приведение текста-числа в арифметике (`="5"+1` = 6).
- Плавающая точка: Excel показывает 15 значащих цифр и «подчищает» хвосты при сравнении.

Идеи для интерфейса (принято): автораскрытие строки формул; поиск функций с
опечатками в «Вставить функцию»; рамка и ошибка #ПЕРЕНОС! для динамических массивов;
контекстная вкладка «Конструктор таблиц» только при выделенной умной таблице.

## Задание 4 (вместо NotebookLM) — вёрстка docx
Элементы, влияющие на разбиение на страницы: `pageBreakBefore`, `keepNext`,
`keepLines`, `widowControl`, `br type=page`, `lastRenderedPageBreak`.
Ключевое: **`lastRenderedPageBreak`** — где Word в последний раз разбил страницу.
Можно использовать как контрольную точку в автотестах вёрстки: если наш разрыв
совпадает с записанным Word — хорошо. Блок `w:compat` (флаги совместимости) меняет
алгоритм переноса — поддерживать обязательно.
