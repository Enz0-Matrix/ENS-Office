# ENS-Office — концепция и план (черновик v0.1, 16.10.2026)

## 1. Честная оценка: можем ли мы это сделать?

**Да, но не «с нуля» и не всё сразу.** MS Office — это десятки лет работы тысяч людей.
Реалистичная цель: собрать продукт из зрелых опенсорс-движков + свой интерфейс
в стиле Office 2021–2024 + своя надёжная подсистема сохранения.

Самые сложные места (по убыванию):
1. **Вёрстка Word-документов 1:1 с MS Word** (разбиение на страницы, таблицы, сноски,
   колонтитулы, обтекание). Именно здесь «плывут» и Р7, и Libre.
2. **Полная совместимость .docx/.xlsx** (сотни редких фич формата OOXML).
3. **Формулы Excel** — 500+ функций с точной семантикой (даты, округление, ошибки).
4. Совместная работа в реальном времени.

Интерфейс (лента, вкладки, диалоги) — наоборот, самая решаемая часть.

## 2. Что не так у конкурентов → наши требования

| Проблема Р7 / Libre | Наше решение (обязательное требование) |
|---|---|
| Зависает на меньших объёмах | Движок таблиц на Rust, ленивый рендер (рисуем только видимые ячейки), пересчёт в фоновом потоке, бенчмарки в CI на файлах 100k–1M строк |
| Неверные/задержанные результаты формул | Набор эталонных тестов: тысячи формул, результаты сверены с реальным Excel |
| Сохраняет прямо в исходный файл во время правки | **Никогда** не писать в исходник без явного «Сохранить». Автосохранение — только в отдельный журнал восстановления |
| Теряет часы работы, «не даёт сохранить» без объяснений | Атомарное сохранение (запись во временный файл → fsync → замена), понятное сообщение *почему* не сохранилось + кнопка «Сохранить как…» в другое место |
| Падение = потеря данных | Журнал изменений (каждые N секунд/операций) + восстановление при следующем запуске, как AutoRecover в Office |
| Таблица открывается в текстовом редакторе | Определять тип по **содержимому** файла (сигнатура, `[Content_Types].xml`), а не только по расширению; единый «лаунчер» маршрутизирует файл в нужное приложение |
| Непривычный интерфейс | Копируем раскладку лент, вкладок, горячих клавиш, контекстных меню Office 2021–2024 |

## 3. Интерфейс в стиле MS Office: что можно, что нельзя

- **Можно:** расположение кнопок, структура вкладок (Главная, Вставка, Макет…),
  логика, горячие клавиши, поведение — это не защищено авторским правом в РФ так,
  как изображения.
- **Иконки:** нельзя брать иконки Office напрямую. Но Microsoft выложила
  **Fluent UI System Icons под лицензией MIT** — это официальный набор в том же стиле,
  его можно использовать легально. (проверить покрытие нужных значков)
- **Шрифты:** Calibri/Cambria/Aptos проприетарные. Используем метрически-совместимые
  свободные: Carlito (=Calibri), Caladea (=Cambria), Liberation Sans/Serif/Mono
  (=Arial/Times New Roman/Courier New). Это важно для одинаковой вёрстки.
- **Названия (утверждено):** Ens-Office, ENS-Tekst, ENS-Table, далее по аналогии.
- **Принцип визуала (утверждено):** узнаваемость важнее оригинальности — всё лежит
  там же, где в Office, чтобы ничего не приходилось искать. Отличия только там,
  где этого требуют авторские права (иконки, шрифты, названия).
- **Главный приоритет — стабильность** (не терять данные, не зависать, считать верно).

Принятые решения — в [02-decisions.md](02-decisions.md); итоги исследования —
в [research/round-1-summary.md](research/round-1-summary.md).

## 4. Модульная установка (уровни функций)

1. **Базовый минимум** — у всех: ввод, форматирование, таблицы, печать, основные формулы.
2. **Пользовательский минимум** — мастер первого запуска: галочки по группам
   («Сводные таблицы», «Рецензирование», «Рассылки», «Макросы», «Финансовые функции»…).
   Лента показывает только включённое → интерфейс проще.
3. **Дополнительно** — включается в любой момент через «Файл → Параметры → Модули».

Технически: каждый модуль = плагин с манифестом (какие кнопки ленты добавляет,
какие функции регистрирует). Код можно грузить лениво — это ещё и ускоряет запуск.

## 5. Варианты архитектуры

### Вариант A — форк ONLYOFFICE (на нём построен сам Р7)
+ быстрый старт, уже есть лента и совместная работа.
− лицензия AGPL v3, тот же движок → унаследуем те же проблемы, что у Р7. **Не рекомендую.**

### Вариант B — ядро LibreOffice + новый интерфейс (через LibreOfficeKit)
+ лучшая совместимость форматов среди опенсорса, MPL 2.0.
− огромная старая C++-кодовая база, производительность Calc — как раз то, на что жалуются.

### Вариант C — собственный стек на современных компонентах (**рекомендую**)
- **Оболочка:** Tauri 2 (Rust + веб-интерфейс). Одна кодовая база →
  Linux (РЕД ОС, Astra), Windows, macOS, Android, iOS. Лёгкая, в отличие от Electron.
- **Интерфейс:** TypeScript, своя лента в стиле Office, Fluent-иконки.
- **Таблицы:** движок **IronCalc** (Rust, MIT/Apache-2.0, чтение/запись xlsx,
  300+ функций Excel, LET/LAMBDA) — дорабатываем недостающее. Рендер сетки на Canvas.
- **Текст:** редактор на модели документа + **собственный движок постраничной вёрстки**
  (самая трудная часть, начинаем с неё как с исследования). Чтение/запись docx — своя
  библиотека на Rust (есть заготовки: `docx-rs`).
- **Запасной путь совместимости:** LibreOffice в фоновом режиме как конвертер для
  экзотических форматов (.doc, .xls, .odt) — опционально.
- **Совместная работа (этап 3):** CRDT (Yjs / Automerge) — работает и по локальной
  сети, и через интернет, и офлайн с последующим слиянием.
- **Связи между файлами:** внешние ссылки вида `[Бюджет.xlsx]Лист1!A1` как в Excel,
  с фоновым отслеживанием изменений исходного файла.

Также стоит посмотреть **Univer** (TypeScript, таблицы+документы+слайды;
лицензию и что вынесено в платную версию — проверить).

## 6. Этапы

| Этап | Результат | Ориентир |
|---|---|---|
| 0. Исследование | Этот документ + отчёты помощников, выбор стека, прототипы вёрстки и сетки | 2–4 недели |
| 1. Каркас | Оболочка Tauri, лента, файловая подсистема (атомарное сохранение, восстановление, определение типа файла), сборка под РЕД ОС | 1–2 мес |
| 2. Таблицы MVP | Открыть/редактировать/сохранить xlsx, базовые формулы, форматирование, 100k строк без тормозов | 2–4 мес |
| 3. Текст MVP | docx: абзацы, стили, списки, таблицы, колонтитулы, печать | 3–6 мес |
| 4. Модули | Мастер первого запуска, плагины, сводные таблицы, рецензирование | далее |
| 5. Совместная работа, мобильные версии, презентации | | далее |

Сроки зависят от того, сколько людей/времени, — с ИИ-помощниками быстрее, но
**тестирование на реальных документах компании — за вами** (это ключевой ресурс).

## 7. Как разбить репозиторий

```
ENS-Office/
  docs/            концепция, требования, решения (ADR)
  core/files/      сохранение, восстановление, определение типа (Rust)
  core/sheets/     движок таблиц (IronCalc + доработки)
  core/docs/       модель документа + вёрстка (Rust)
  ui/shell/        лента, окна, параметры (TypeScript)
  ui/sheets/  ui/text/
  app/             Tauri-оболочка, сборка под ОС
  tests/corpus/    набор реальных docx/xlsx для проверки
```
